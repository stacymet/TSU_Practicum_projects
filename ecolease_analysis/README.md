# EcoLease Solutions — анализ и проектирование клиентского сервиса

## О проекте

Учебный кейс по бизнес- и системному анализу, посвящённый модернизации клиентских процессов лизинговой компании.

> **Важно:** EcoLease Solutions Ltd. — компания, существующая исключительно в рамках учебного кейса. Проект не связан с реальной организацией.

В рамках проекта проведено обследование текущих процессов, определены потребности и заинтересованные стороны, сформированы требования к целевому решению и разработаны материалы для его проектирования.

## Задачи проекта

* проанализировать текущие процессы взаимодействия с клиентами;
* определить основные проблемы и потребности пользователей;
* выявить заинтересованные стороны и их ожидания;
* описать целевую концепцию решения;
* сформировать функциональные и нефункциональные требования;
* разработать пользовательские сценарии и User Stories;
* описать клиентский путь с помощью CJM;
* разработать концептуальную модель данных;
* создать прототипы интерфейсов;
* проработать пользовательский интерфейс в Figma.

## Артефакты проекта

### Анализ контекста и концепции проекта

Документ включает анализ изменений, потребностей, возможных решений, заинтересованных сторон, ценности и контекста проекта. В качестве ключевой проблемы рассматривается высокая доля ручных операций во взаимодействии с клиентами.

### Customer Journey Map (CJM)

Карта клиентского пути для анализа взаимодействия пользователя с компанией, выявления проблемных точек и возможностей для улучшения клиентского опыта.

### Use Case Scenarios

Сценарии использования системы, описывающие взаимодействие пользователей с функциональностью будущего решения.

### User Stories

Пользовательские истории, сформированные с позиции различных категорий пользователей системы и их потребностей.

### Функциональные требования

Описание функций и возможностей целевой системы, необходимых для поддержки клиентских и внутренних процессов.

### Нефункциональные требования

Требования к качественным характеристикам системы, включая ограничения и условия её эксплуатации.

### Концептуальная модель данных

Модель основных сущностей предметной области и связей между ними, подготовленная для дальнейшего проектирования информационной системы.

### Прототипирование

Прототипы пользовательских интерфейсов и сценариев взаимодействия с системой.

Часть прототипирования выполнена в **Figma**.

### Диаграмма состояний

Диаграмма, отражающая возможные состояния объекта и переходы между ними в процессе работы системы.

## Концепция решения

В рамках кейса в качестве целевого решения рассматривается **личный кабинет клиента**, который должен стать единым цифровым каналом взаимодействия с компанией.

Предусмотрена работа как с клиентами, так и с внутренними пользователями — клиентскими менеджерами, сотрудниками отдела договоров, маркетинга и администраторами системы.

Основные рассматриваемые возможности:

* управление профилем клиента;
* просмотр информации о договорах и платежах;
* онлайн-оплата;
* работа с документами;
* подача и отслеживание заявок;
* уведомления;
* обратная связь и поддержка;
* обработка заявок сотрудниками;
* работа с клиентскими данными и аналитикой.

Концепция также предусматривает интеграцию с внешними и внутренними системами, включая бухгалтерскую систему, платёжный шлюз, CRM и систему электронного документооборота.

## Результат

В результате подготовлен комплекс аналитических и проектных артефактов, описывающих переход от текущих процессов к целевому клиентскому сервису:

* анализ контекста и потребностей;
* CJM;
* User Stories;
* Use Case Scenarios;
* функциональные требования;
* нефункциональные требования;
* концептуальная модель данных;
* прототипы интерфейсов;
* диаграмма состояний;
* макеты в Figma.

Проект демонстрирует применение инструментов бизнес- и системного анализа на полном цикле учебного кейса — от анализа проблемы и потребностей пользователей до формирования требований и прототипирования решения.

## Инструменты

* **Figma** — прототипирование и проектирование интерфейсов;
* **UML / Use Case** — описание взаимодействия пользователей с системой;
* **CJM** — анализ клиентского пути;
* **User Story** — формализация пользовательских потребностей;
* **моделирование данных** — разработка концептуальной модели;
*  **Draw.io** - проектирование блок-схем;
* **бизнес- и системный анализ** — формирование требований и концепции решения.
